LLM API 클라이언트: 모델을 안전하게 부르기

백엔드 > LLM 활용

💡 한 문장으로

LLM은 원격 서버에 있어서, SDK로 요청을 보내고 응답을 받아요. 앱은 키를 안전하게 두고, 답을 정해진 모양으로 받고, 실패를 종류별로 다루고, 비용을 기록해야 해요.

🤔 왜 필요할까?

LLM은 보통 내 컴퓨터가 아니라 회사의 서버에서 돌아가요. 우리 프로그램은 인터넷으로 요청을 보내고 응답을 받아요. 이 요청을 직접 HTTP로 짜도 되지만, 키를 붙이고, 응답 JSON을 풀고, 실패하면 다시 보내는 일을 매번 하게 돼요. 그래서 회사가 주는 SDK(그 API를 쓰기 쉽게 감싼 라이브러리)를 써요. 여기서는 OpenAI의 파이썬 SDK와 Responses API를 써요.

그런데 SDK를 쓰더라도 앱이 직접 정해야 하는 게 있어요.

무엇을왜
키를 어디에 두나키가 코드에 들어가면 공유할 때 같이 새요. 남이 쓰면 비용이 내게 청구돼요.
답을 어떤 모양으로 받나글로 받으면 프로그램이 쓰기 어려워요.
실패하면 어떻게 하나키 문제, 너무 잦은 요청, 할당량, 서버 오류, 시간 초과는 각각 대처가 달라요.
얼마나 썼나호출마다 토큰 수만큼 돈이 들어요.

그래서 목표는 안전하게 클라이언트를 만들고, 답을 정해진 모양으로 받고, 실패를 종류별로 다루고, 사용량을 기록하는 거예요.

🗺️ 통째로 한 번

클라이언트 하나를 만들어 두고, 보내기, 모양 정해 받기, 실패 다루기, 조각으로 받기, 비용 기록을 차례로 붙여요. 상자를 누르면 그 단계로 가요.

이 페이지는 실제 OpenAI 서버에 요청을 보내지 않아요 (키와 비용 없음). SDK에 가짜 서버를 붙여서, SDK가 실제로 만드는 요청, 실제로 던지는 예외, 실제로 보내는 횟수를 관찰했어요. 응답 글과 토큰 수(입력 31, 출력 36)는 실제 호출 기록에서 가져온 값이에요.

코드 읽기

코드뜻
openai.AuthenticationError401. 키가 틀렸거나 없음. 다시 보내도 같아요.
openai.RateLimitError429. 너무 자주 보냈거나(rate_limit_exceeded) 할당량을 다 썼거나(insufficient_quota)
e.code같은 예외 안에서 원인을 가르는 값

코드의 ⑤ 부분

⑤ 나오는 대로 받기 (스트리밍)

답이 다 만들어지길 기다리지 않고, 만들어지는 조각을 바로바로 받아요.

긴 답은 다 만들어지는 데 몇 초가 걸려요. 스트리밍은 서버가 조각을 보내는 대로 받아서, 사용자가 글이 써지는 걸 바로 볼 수 있게 해요.

코드뜻
with client.responses.stream(...) as stream스트리밍 연결을 열고, 블록이 끝나면 닫아요.
event.type == "response.output_text.delta"글 조각이 왔다는 이벤트. 다른 이벤트(시작, 끝 등)도 와요.
event.delta새로 온 글 조각

🛠️ 실제로 할 때

      
상황어떻게
키를 저장한다.env 파일에 두고 python-dotenv로 읽거나, 운영 환경의 비밀 저장소를 써요. .env는 꼭 .gitignore에 넣어요.
같은 질문이 반복된다질문, 모델, 지시가 같으면 답을 저장해 두고 다시 쓰면(캐시) 비용이 줄어요. 캐시 열쇠에 Prompt 판 번호도 넣어서, 틀이 바뀌면 새로 묻게 해요.
재시도를 직접 정한다max_retries=0으로 SDK 재시도를 끄고, e.code와 응답의 retry-after 시간을 보고 직접 기다렸다 보내요. 전체 시간 한도를 정해 두지 않으면 사용자가 무한정 기다려요.
모델을 고른다간단한 질문은 싸고 빠른 모델, 어려운 질문은 비싼 모델로 보내는 식으로 나눌 수 있어요. 모델 이름을 환경 변수로 둔 이유예요.

      
📦 이 코드에 쓴 라이브러리

      
단계함수하는 일
①OpenAI(timeout=, max_retries=)클라이언트 (openai)
②client.responses.create(), output_text, usage보내고 받기
③client.responses.parse(text_format=), output_parsed구조화 출력 (openai + pydantic)
④AuthenticationError, RateLimitError, APITimeoutError, APIStatusError예외 종류
⑤client.responses.stream(), event.delta, get_final_response()스트리밍
⑥decimal.Decimal정확한 비용 계산 (표준 라이브러리)
