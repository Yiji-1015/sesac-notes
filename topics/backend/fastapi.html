FastAPI로 지식 API 만들기

백엔드 > API 서버

💡 한 문장으로

API 서버는 다른 프로그램이 데이터를 읽고 쓰는 하나의 정해진 입구예요. FastAPI로 주소마다 함수를 연결하고, 들어오는 입력은 저장하기 전에 검사해요.

🤔 왜 필요할까?

API는 다른 프로그램이 이 서비스의 기능을 쓰는 정해진 입구예요. 웹 화면, 다른 서버, AI Agent가 모두 같은 입구로 "지식 목록 줘", "이거 저장해 줘"를 요청해요. 요청과 응답은 보통 HTTP(웹 주소로 요청을 보내고 답을 받는 규칙)로 주고받아요.

예제는 지식 항목(제목, 분류, 내용)을 JSON 파일에 저장하는 작은 서비스예요. 파일은 이렇게 생겼어요.

idtitlecategorycontent
1가상환경setup프로젝트별 패키지를 분리한다.
2서버 실행apiuvicorn으로 개발 서버를 켠다.
3입력 오류api422이면 입력값을 확인한다.

그냥 각 프로그램이 이 파일을 직접 열어 읽고 쓰면 안 될까요? 누군가 category를 빠뜨린 항목을 파일에 직접 넣으면 이렇게 돼요.

입구를 하나로 모으면, 들어오는 모든 데이터를 같은 규칙으로 검사하고, 저장 방식이 파일에서 DB로 바뀌어도 바깥 프로그램은 몰라도 돼요. 여기서는 파이썬 웹 프레임워크 FastAPI로 이 입구를 만들어요.

그래서 목표는 지식을 조회, 등록, 수정, 삭제하는 입구를 만들고, 잘못된 요청은 저장 전에 막고, 결과를 알맞은 상태 코드(요청이 어떻게 됐는지 알려 주는 세 자리 숫자)로 알려 주는 거예요.

🗺️ 통째로 한 번

요청 하나가 들어오면 FastAPI가 주소와 방식(GET, POST 등)으로 함수를 찾고, 입력을 검사한 뒤 함수를 불러요. 함수는 파일을 읽고 쓰고, 돌려준 값은 JSON 응답이 돼요. 상자를 누르면 그 단계로 가요.

아래에서 ①부터 ⑥까지, main.py 파일 하나가 자라는 모습을 따라가요. 결과는 모두 FastAPI의 TestClient(서버를 띄우지 않고 요청을 보내 보는 도구)로 실제로 보낸 요청이에요.

코드의 ③ 부분

③ 조회하기 (GET)

목록 주소와 번호 하나 주소를 만들어요. 없는 번호는 404로 알려요.

주소에는 값을 두 가지 방법으로 실을 수 있어요. 주소 안에 넣는 경로 매개변수(/knowledge/2)와, ? 뒤에 붙이는 쿼리 매개변수(?category=api)예요. 보통 "무엇을"은 경로에, "어떻게 거를지"는 쿼리에 둬요.

코드뜻

코드의 ④ 부분

④ 입력 모양 정하고 등록하기 (POST)

Pydantic으로 "등록할 때 보내야 하는 모양"을 정하고, 통과한 것만 저장해요.

Pydantic은 "이 데이터는 이런 필드와 타입이어야 한다"를 클래스로 적어 두면 검사해 주는 라이브러리예요. 함수 인자 타입을 이 클래스로 두면, FastAPI가 요청 본문(JSON)을 이 모양으로 검사한 뒤에만 함수를 불러요.

코드 읽기

코드뜻
class KnowledgeWrite(BaseModel)등록과 수정 때 받을 모양. id는 없어요. 서버가 정하니까요.
Field(min_length=1, max_length=80)빈 글이나 너무 긴 글을 막아요.
payload: KnowledgeWrite요청 본문을 이 모양으로 검사해서 객체로 받아요.
payload.model_dump()객체를 다시 dict로. 저장하려고요.
{"id": data["next_id"], **payload.model_dump()}서버가 정한 번호에 받은 필드를 펼쳐 붙여요.
@app.post("/knowledge", status_code=201)성공하면 200 대신 201(새로 만듦)

🛠️ 실제로 할 때

      
상황어떻게
두 요청이 동시에 저장한다둘 다 파일을 읽고, 각자 하나를 추가하고, 각자 저장하면 먼저 저장한 쪽이 사라져요. threading.Lock으로 "읽기부터 저장까지"를 한 번에 하나만 하게 막을 수 있지만, 서버가 여러 개면 소용없어요. 이게 DB를 쓰는 가장 큰 이유예요 (PostgreSQL).
항목이 많아진다지금은 요청마다 파일 전체를 읽고 써요. 항목이 수만 개가 되면 느려져요. 이것도 DB가 필요한 이유예요.
주소 순서가 겹친다/knowledge/search와 /knowledge/{knowledge_id}가 둘 다 있으면 먼저 등록한 쪽이 이겨요. 고정 주소를 먼저 등록해요.
422 응답을 사용자에게 보여 준다detail의 loc(어디)와 msg(왜)를 그대로 보여 주면 무엇을 고칠지 알 수 있어요.
--reload코드가 바뀔 때마다 서버를 다시 띄우는 개발용 옵션이에요. 실제 운영에서는 빼요.

      
📦 이 코드에 쓴 라이브러리

      
단계함수하는 일
①FastAPI(), @app.get앱 만들기, 주소에 함수 연결 (fastapi)
②Path.read_text(), json.loads(), json.dumps()파일 저장소 (표준 라이브러리)
③HTTPException(status_code, detail)실패 응답 보내기 (fastapi)
④BaseModel, Field(), model_dump(), @app.post(status_code=201)입력 모양 검사 (pydantic), 등록
⑤ ⑥@app.put, @app.delete(status_code=204)수정, 삭제
확인TestClient(app).get(), .post(json=...)서버 없이 요청 보내 보기 (fastapi.testclient)

      
read_data, write_data와 각 주소의 함수는 이 파일 안에서 정의한 함수예요.
