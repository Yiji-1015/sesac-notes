FastAPI와 PostgreSQL 연동: API 요청을 DB 행으로

백엔드 > 데이터베이스

💡 한 문장으로

API가 받은 요청을 DB에 저장하려면 연결(Session), 객체와 행의 변환(ORM), DB 오류를 응답으로 바꾸기를 정해야 해요. SQLAlchemy가 앞의 둘을 맡아요.

🤔 왜 필요할까?

API 서버는 지식을 JSON 파일에 저장했고, PostgreSQL 기초에서는 SQL로 DB를 다뤘어요. 이제 둘을 이어서, API가 받은 요청을 DB에 저장해요.

파일 읽기, 쓰기를 SQL로 바꾸기만 하면 될 것 같지만, 실제로는 세 가지를 새로 정해야 해요.

무엇을왜어디서
DB 연결을 언제 열고 닫나요청마다 연결을 새로 만들면 느리고, 닫는 걸 잊으면 연결이 바닥나요.③ Session
파이썬 객체와 테이블 행을 어떻게 오가나SQL 문자열과 결과 튜플을 손으로 다루면 실수가 잦아요.② ORM
DB 오류를 어떤 응답으로 바꾸나규칙 위반을 그냥 두면 모두 500(서버 고장)으로 보여요.⑥ 오류 처리

여기서는 SQLAlchemy를 써요. 파이썬 클래스로 테이블을 적으면 SQL을 대신 만들어 주는 도구(ORM, Object Relational Mapping)이고, 연결과 트랜잭션도 관리해 줘요.

🗺️ 통째로 한 번

요청이 오면 FastAPI가 Session을 하나 열어 함수에 넘기고, 함수는 파이썬 객체로 DB를 다루고, SQLAlchemy가 그걸 SQL로 바꿔 보내요. 응답을 보내면 Session을 닫아요. 상자를 누르면 그 단계로 가요.

실제로 POST /knowledge 하나를 보냈을 때 DB로 간 SQL이에요. 파이썬 코드에는 SQL이 한 줄도 없는데, 이만큼이 오갔어요.

결과는 모두 노트 전용 연습 DB를 새로 만들어 app.py를 단계별로 실행하고 TestClient로 요청을 보낸 값이에요.

코드의 ③ 부분

③ 요청마다 Session 하나

요청 하나가 Session 하나를 쓰고, 요청이 끝나면 닫히게 해요.

Session은 "이번 작업에서 읽고 바꾼 것"을 모아 두었다가 한 트랜잭션으로 DB에 보내는 작업 공간이에요. 요청끼리 Session을 같이 쓰면 한 요청의 실패가 다른 요청까지 취소해요. 그래서 요청마다 새로 만들어요.

코드 읽기

코드뜻
sessionmaker(engine)Session을 찍어 내는 틀
def get_session(): with SessionLocal() as session: yield sessionyield로 Session을 넘겨주고, 요청이 끝나면 돌아와서 with를 나가며 닫아요.
session: Session = Depends(get_session)FastAPI가 요청마다 get_session()을 불러 그 결과를 이 인자로 넣어 줘요 (의존성 주입).

⑥ DB 오류를 알맞은 응답으로

IntegrityError(DB 규칙 위반)가 나면 500 대신 409(충돌)로 답해요.

⑤에서 같은 제목을 두 번 보내면 500이 났어요. 500은 "서버가 고장 났다"는 뜻이라, 클라이언트는 다시 보내면 될지, 입력을 고쳐야 할지 알 수 없어요. 원인별로 다른 응답을 줘야 해요.

🛠️ 실제로 할 때

      
상황어떻게
테이블 구조를 바꿔야 한다create_all()은 이미 있는 테이블을 고치지 않아요. Alembic으로 "무엇을 어떻게 바꿨는지"를 마이그레이션 파일로 남기고 alembic upgrade head로 적용해요. DB 구조의 Git 같은 거예요. 자세한 내용은 옛 Day19 노트를 보세요.
응답이 이상하다가장 먼저 어느 DB에 붙었는지 확인해요 (①의 engine.url). 연습 DB와 실제 DB를 헷갈리는 경우가 많아요.
ORM 모델과 Pydantic 모델ORM 모델(Knowledge)은 DB 행의 모양, Pydantic 모델(KnowledgeCreate)은 요청의 모양이에요. 등록할 때는 id가 없고 분류를 이름으로 받는 것처럼 둘은 달라요. 하나로 합치지 않아요.
요청이 많아진다Engine의 연결 풀 크기(pool_size)만큼만 동시에 DB를 써요. 요청이 끝나면 연결을 돌려주는 ③이 중요한 이유예요.

      
📦 이 코드에 쓴 라이브러리

      
단계함수하는 일
①create_engine(url), engine.connect(), text()연결 (SQLAlchemy)
②DeclarativeBase, Mapped, mapped_column(), ForeignKey, metadata.create_all()ORM 모델과 테이블
③sessionmaker(), Depends()요청마다 Session (SQLAlchemy, FastAPI)
④~⑦select(), session.scalars(), session.get(), add(), commit(), refresh(), delete()읽고 쓰기 (SQLAlchemy)
⑥IntegrityError, @app.exception_handler, JSONResponseDB 오류를 응답으로

      
get_session, to_dict와 각 주소의 함수는 이 파일 안에서 정의한 함수예요.
