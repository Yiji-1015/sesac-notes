인덱싱: 조각을 DB에 넣고 검색하기

문서 적재 3/3쪽  |  이전: 2쪽 Chunking  |  처음: 1쪽 문서 읽기

💡 한 문장으로

인덱싱은 조각을 벡터와 함께 DB에 저장해서 질문과 가까운 조각을 찾을 수 있게 하고, 확인이 끝난 판만 검색에 보이게 하는 단계예요.

🤔 왜 필요할까?

입력은 2쪽에서 만든 조각 13개(chunks.json)예요. 이걸 검색에 쓰려면 세 가지가 필요해요.

필요 1. 질문과 비슷한 조각을 찾기

2쪽 "왜"에서 본 것처럼, 비슷한지는 텍스트를 숫자 목록(벡터)으로 바꿔 거리를 재서 판단해요. 질문이 올 때마다 모든 조각의 벡터를 새로 만들면 느리니까, 조각의 벡터는 미리 만들어 저장해 두고 질문의 벡터만 그때 만들어요.

저장과 거리 계산, 가까운 순 정렬은 DB에 맡겨요. 여기서는 PostgreSQL에 벡터 기능을 더하는 확장 pgvector를 써요. 같은 DB에 출처, 판 번호 같은 정보도 함께 둘 수 있어요.

필요 2. 문서는 바뀌어요

도서관이 대출 기간을 14일에서 21일로 바꿨다고 해 볼게요. 새 글로 조각을 다시 만들어 넣을 때, 옛 조각과 새 조각을 구분 없이 한 테이블에 두면 이렇게 돼요. 실제로 두 판을 다 넣고 "대출 기간은 며칠인가요?"로 검색한 결과예요.

"14일"과 "21일"이 둘 다 위에 나와요. LLM은 어느 쪽이 지금 규정인지 알 수 없어요. 그래서 조각마다 판 번호(version)를 붙이고, 문서마다 "지금 공개된 판"을 따로 적어 둬요.

필요 3. 바꾸는 도중에도 검색은 계속돼요

새 판을 넣는 도중에 검색이 들어오면, 반쯤 들어간 새 판이 보이면 안 돼요. 그래서 새 판은 먼저 다 넣고, 개수가 맞는지 확인한 다음, 한 번에 공개해요. 확인에 실패하면 공개하지 않아서 옛 판이 그대로 보여요.

그래서 이 단계는 벡터를 만들고, 판 번호와 함께 저장하고, 확인한 뒤 공개하고, 공개된 판에서만 검색해요.

🗺️ 통째로 한 번: 조각 13개가 검색되기까지

상자를 누르면 그 단계로 이동해요.

아래에서 ⑭부터 ⑱까지 한 단계씩 따라가요. 1쪽(①~⑦)과 2쪽(⑧~⑬)에 이어서 같은 파일이 계속 자라요. 오른쪽 코드에서 앞 쪽 부분은 접혀 있어요.

🔎 한 단계씩: 설명과 코드를 나란히

코드의 ⑭ 부분

⑭ 벡터 만들기

조각마다 256칸짜리 벡터를 만들어요.

먼저 밝혀 둘 것: 이건 임시 벡터예요

원래는 Embedding 모델(예: multilingual-e5-small)로 벡터를 만들어야 하지만, 이 PC에는 한국어 Embedding 모델이 없어요. 그래서 대신 "글자 2개 묶음을 256칸에 나눠 세는" 벡터를 써요. 뜻이 아니라 글자가 겹치는 정도만 반영해요. 코드에서 embed() 안만 바꾸면 Embedding 모델로 갈아 끼울 수 있게 함수로 나눠 뒀어요.

질문 하나가 어떻게 숫자가 되는지 실제로 보면:

글자 2개 묶음마다 정해진 칸(256칸 중 하나)에 1을 더하고, 마지막에 벡터 길이가 1이 되도록 나눠요. 길이가 1인 벡터끼리는 곱해서 더한 값(내적)이 바로 코사인 유사도예요. 두 벡터가 같은 방향이면 1, 겹치는 게 없으면 0이에요. DB에서는 이걸 거리로 써요: 코사인 거리 = 1 − 코사인 유사도. 작을수록 가까워요.

코드 읽기

코드뜻
analyzer="char_wb", ngram_range=(2, 2)단어 안에서 글자 2개씩 묶기. 단어 앞뒤에 공백을 붙여서 "단어의 시작과 끝"도 묶음이 돼요.
n_features=DIM칸 수(256). 묶음마다 해시로 칸을 정해서, 사전을 만들 필요가 없어요.
alternate_sign=False칸에 언제나 더하기만. 기본값은 빼기도 섞어요.
norm="l2"벡터 길이를 1로 맞추기
.toarray().astype(np.float32)대부분 0인 "희소 행렬"을 보통 배열로, 32비트 실수로. pgvector는 32비트 실수를 저장해요.
embed_text(c)2쪽에서 찾은 섹션 제목을 본문 앞에 붙여요. "열람실" 같은 제목이 본문에 없어도 검색에 걸리게요.

코드의 ⑮ 부분

⑮ 테이블 만들기

DB에 접속해서 테이블 두 개를 만들어요. 문서마다 공개된 판을 적는 documents, 조각과 벡터를 담는 chunks예요.

chunks의 기본 키는 (파일, 판, 조각 ID) 세 개를 합친 거예요. 그래서 같은 조각이 판 1에도, 판 2에도 있을 수 있어요. 대신 같은 판에 같은 조각이 두 번 들어갈 수는 없어요.

코드 읽기

코드뜻
psycopg.connect()접속 정보를 인자로 주지 않으면 환경 변수 PGHOST, PGPORT, PGUSER, PGPASSWORD, PGDATABASE에서 읽어요. 비밀번호를 코드에 적지 않으려고요.
CREATE EXTENSION IF NOT EXISTS vector이 DB에서 pgvector를 켜요. vector 타입과 거리 연산자가 생겨요.
register_vector(conn)파이썬의 numpy 배열과 DB의 vector 타입을 서로 바꿔 주도록 등록해요.
CREATE TABLE IF NOT EXISTS이미 있으면 그냥 넘어가요. 다시 실행해도 안전해요.

REFERENCES documents (file)documents에 없는 파일의 조각은 넣을 수 없어요.
location2쪽의 where(쪽 정보)예요. WHERE는 SQL 문법 단어라 열 이름을 바꿨어요.

상황어떻게

        
Embedding 모델로 바꾸기embed() 안을 Embedding 모델 호출로 바꾸고, DIM을 그 모델의 차원으로 맞춰요 (예: multilingual-e5-small은 384). e5 계열은 질문 앞에 "query: ", 조각 앞에 "passage: "를 붙여 쓰라고 안내해요 (공식 문서). 자세한 내용은 Embedding 노트를 보세요.

        
조각이 아주 많다지금은 모든 조각과 거리를 재요. 수십만 개가 되면 CREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops)로 근사 검색 인덱스를 만들어요. 아주 조금 덜 정확한 대신 훨씬 빨라요.

        
판마다 조각을 전부 다시 넣는 게 아깝다지금은 판 2에도 바뀌지 않은 조각까지 다시 넣어요(단순하고 확인이 쉬워요). 조각이 많으면 2쪽의 chunk_id로 바뀐 조각만 찾아 새로 벡터를 만들고, 나머지는 재사용하는 방식도 있어요.

        
옛 판 정리공개가 바뀐 뒤에도 옛 판은 잠시 남겨 두면, 문제가 생겼을 때 published만 되돌려 바로 복구할 수 있어요. 일정 기간이 지나면 지워요.

        
두 작업이 동시에 공개하려 한다⑰에서 SELECT … FROM documents WHERE file = %s FOR UPDATE로 그 문서 행을 먼저 잠그면, 한쪽이 끝날 때까지 다른 쪽이 기다려요.
