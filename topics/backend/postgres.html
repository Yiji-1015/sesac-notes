PostgreSQL 기초: 지식을 테이블에 저장하고 꺼내기

백엔드 > 데이터베이스

💡 한 문장으로

PostgreSQL은 데이터를 표(테이블)로 저장하는 DB예요. 여러 요청이 동시에 써도 안전하고, 규칙을 DB가 지키고, 여러 작업을 한 묶음으로 확정하거나 취소할 수 있어요.

🤔 왜 필요할까?

지금까지 지식은 JSON 파일에 저장했어요 (API 서버). 파일은 간단하지만, 여러 요청이 동시에 쓰면 문제가 생겨요. 실제로 20개 작업이 동시에 항목 하나씩을 추가해 봤어요.

DB(데이터베이스)는 데이터를 여러 사용자가 동시에 안전하게 저장하고 찾을 수 있게 관리하는 프로그램이에요. 그중 PostgreSQL은 표(테이블) 모양으로 데이터를 저장하는 관계형 DB이고, SQL이라는 언어로 "넣어라", "찾아라"를 요청해요.

DB가 파일보다 나은 점은 세 가지예요.

  • 동시에 써도 안전해요. (위 결과)
  • 규칙을 DB가 지켜요. "분류 이름은 비울 수 없다", "없는 분류를 가리킬 수 없다" 같은 규칙을 걸어 두면, 코드에 실수가 있어도 DB가 거부해요.
  • 여러 작업을 한 묶음으로 처리해요. 하나라도 실패하면 전부 취소해서 반쪽짜리 상태가 남지 않아요.

예제는 지식과 분류를 두 테이블로 나눠 저장해요. 파이썬에서는 psycopg로 PostgreSQL에 접속해요.

🗺️ 통째로 한 번

접속 → 테이블 설계 → 넣기 → 꺼내기 → 연결해서 읽기 → 바꾸기 → 묶어서 처리하기 → 빠르게 찾기 순서예요. 상자를 누르면 그 단계로 가요.

결과는 모두 노트 전용 연습 DB를 새로 만들어 basics.py를 단계별로 실행한 값이에요. 실행이 끝나면 DB는 지웠어요.

① 접속하기

코드의 ② 부분

② 테이블 두 개 만들기

분류(categories)와 지식(knowledge) 테이블을 만들고, 지켜야 할 규칙을 같이 걸어요.

분류 이름을 지식마다 글자로 적으면, 이름을 바꿀 때 모든 지식을 고쳐야 하고 오타도 생겨요. 그래서 분류는 따로 두고, 지식은 분류의 번호만 가리켜요.

코드 읽기

코드뜻
bigint GENERATED ALWAYS AS IDENTITY번호를 DB가 1, 2, 3… 자동으로 붙여요. 직접 넣지 못하게 막아요.
PRIMARY KEY기본 키. 행 하나를 가리키는 번호로, 중복과 빈 값이 안 돼요.
NOT NULL비워 둘 수 없어요.
UNIQUE같은 값이 두 번 들어갈 수 없어요.
CHECK (char_length(name) BETWEEN 1 AND 30)값이 조건을 만족해야 해요. 여기서는 1~30글자
REFERENCES categories (id)외래 키. categories에 있는 번호만 넣을 수 있어요.
ON DELETE RESTRICT그 분류를 가리키는 지식이 있으면 분류를 못 지우게 막아요.
conn.commit()지금까지 한 일을 확정해요. psycopg는 기본으로 트랜잭션 안에서 일해서, 확정하지 않으면 접속을 닫을 때 취소돼요.

코드의 ⑦ 부분

⑦ 트랜잭션

여러 작업을 한 묶음으로 처리해서, 하나라도 실패하면 전부 취소해요.

"새 분류를 만들고, 그 분류의 첫 지식을 넣는다"는 두 작업이 함께 되어야 의미가 있어요. 이렇게 전부 되거나 전부 안 되어야 하는 묶음을 트랜잭션이라고 해요.

코드 읽기

코드뜻
with conn.transaction():블록 안의 작업을 한 묶음으로. 블록이 정상으로 끝나면 확정(commit), 오류가 나면 취소(rollback)돼요.
except psycopg.Error as eDB 오류를 잡아요. 오류 종류는 type(e).__name__으로 볼 수 있어요.

⑧ 인덱스와 실행 계획

행을 2만 개로 늘린 뒤, 제목으로 찾는 SQL을 DB가 어떻게 실행하는지 보고, 인덱스를 만들어 비교해요.

DB가 SQL을 어떻게 실행할지 세운 계획을 실행 계획이라고 해요. EXPLAIN을 앞에 붙이면 실행하지 않고 계획만 보여 주고, EXPLAIN ANALYZE는 실제로 실행해서 걸린 시간까지 보여 줘요.

🛠️ 실제로 할 때

      
상황어떻게
같은 스크립트를 두 번 실행한다②의 CREATE TABLE이 "이미 있음" 오류로 멈춰요. 테이블 구조를 바꾸고 기록하는 일은 Alembic 같은 마이그레이션 도구로 해요 (FastAPI와 PostgreSQL 연동).
API에서 DB를 쓴다⑥처럼 0행은 오류가 아니라서, API가 직접 404로 바꿔야 해요. 반대로 ②의 규칙 위반 오류는 409나 422 같은 응답으로 바꿔요.
NULL과 빈 글NULL은 "값이 없음", ''는 "빈 글이라는 값"이에요. WHERE x = NULL은 아무것도 안 걸려요. WHERE x IS NULL로 써요.
인덱스를 어디에 거나자주 찾는 조건(WHERE)과 연결(JOIN)에 쓰는 열에 걸어요. 기본 키에는 자동으로 있어요. 많이 걸수록 쓰기가 느려지니 실행 계획을 보고 정해요.
인덱스는 뜻을 모른다여기서 만든 B-tree 인덱스는 "같은 글자"를 빨리 찾을 뿐, 뜻이 비슷한 글은 못 찾아요. 그건 벡터 검색의 일이에요 (인덱싱).
