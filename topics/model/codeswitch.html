💡 한 문장으로

이 노트 문장의 절반쯤은 한국어 뼈대에 영어 용어가 섞여 있어요(코드 스위칭). 다국어 임베딩도 같은 언어끼리 더 가깝고, 같은 개념을 한국어와 영어로 물으면 찾는 결과가 자주 달라요. 문서 언어에 맞춰 묻거나 두 언어를 함께 적으면 나아져요.

🤔 왜 필요할까?

한국에서 일하는 사람의 글은 "RAG는 Chunking을 먼저 해요"처럼 한국어와 영어가 섞여요. 한 대화나 문장 안에서 언어를 바꿔 쓰는 걸 코드 스위칭이라고 해요. 세계 인구의 절반 넘게가 두 언어 이상을 쓰니 아주 흔한 일인데, LLM에게는 문제이기도 하고 해결책이기도 해요.

문제가 되는 곳도움이 되는 곳
출력 언어섞인 질문에 엉뚱한 언어로 답함 (어느 언어가 뼈대인지 못 알아챔)
안전여러 언어를 섞은 위험한 질문에 안전장치가 덜 걸림
학습단어 → 문장 → 한 언어 순으로 섞인 글을 먼저 배우면 새 언어를 더 잘 배움
추론질문을 조금씩 영어로 바꿔 보여 주면 저자원 언어에서 더 잘 답함

이 쪽은 LLM을 부르지 않고, 이 노트의 문장과 용어집, 그리고 다국어 임베딩 모델 하나로 "섞이면 무엇이 달라지나"를 재 봐요. 임베딩과 벡터 검색을 알면 더 쉬워요.

🗺️ 통째로 한 번

섞인 문장 세기 → 용어 짝과 토큰 → 한국어와 영어로 설명 찾기 → 교차 언어 일관성 → 조금씩 섞기 → 함께 적기. 상자를 누르면 그 단계로 가요.

코드는 examples/codeswitch/mixed_language.py 하나예요. 모델은 다른 쪽에서도 쓰는 multilingual-e5-small이에요.

🔎 한 단계씩: 설명과 코드를 나란히

코드의 ① 부분

① 이 노트 문장은 얼마나 섞여 있나

주제 페이지 본문 문장 1,016개를 띄어쓰기로 나눠, 영어 단어와 "영어 + 한국어 조사" 단어를 세요.

코드 스위칭에서 문장의 문법 뼈대를 이루는 언어를 주언어(matrix language), 끼어든 언어를 삽입 언어(embedded language)라고 해요. 강연의 OLA 연구는 섞인 질문의 13%만 답할 언어를 밝히고, 나머지는 사람이 맥락으로 알아챈다는 점에서 출발해요. 모델은 이런 맥락보다 표면 단서(어느 글자가 많나)에 끌려 엉뚱한 언어로 답하기 쉬워요.

코드의 ③ 부분

③ 한국어로 물을 때, 영어로 물을 때

설명들을 문서로 넣고, 한국어 이름과 영어 이름을 각각 질문으로 넣어 맞는 설명이 위 5개 안에 오는지 봐요.

e5 모델은 질문 앞에 query: , 문서 앞에 passage: 를 붙여 학습했어요. 둘을 같은 공간의 벡터로 바꿔 코사인 유사도가 큰 순으로 줄 세워요.

코드의 ④ 부분

④ 두 언어 모두 찾나: 교차 언어 일관성

같은 용어를 한국어와 영어로 물었을 때 결과가 같은지 짝마다 세요.

정확도만 보면 놓치는 문제예요. 한국어 정확도와 영어 정확도가 비슷해도, 서로 다른 문제를 맞힐 수 있어요. 강연의 CSCL(코드 스위칭 커리큘럼)은 토큰 단위로 섞은 글 → 문장 단위로 섞은 글 → 한 언어 글 순서로 학습해서, 두 언어 모두 맞히는 비율을 26.7%에서 41.6%로 올렸다고 해요.

🛠️ 실제로 할 때

      
상황어떻게
한국어 서비스에서 LLM이 엉뚱한 언어로 답한다시스템 프롬프트에 답할 언어를 분명히 적어요. 강연에서도 언어를 명시하면 거의 완벽하게 지켰어요. 섞인 질문이 많으면 "주언어로 답한 예"로 선호 학습(DPO)을 하기도 해요.
한국어와 영어가 섞인 문서를 검색한다문서와 질문의 언어를 맞추거나, 핵심 용어를 두 언어로 함께 적어 둬요. 다국어 임베딩이어도 같은 언어끼리가 더 가까워요.
안전장치를 만든다영어로만 시험하지 말고, 다른 언어와 섞인 질문으로도 시험해요. 자원이 적은 언어일수록 안전장치가 약해요.

      
📦 이 코드에 쓴 라이브러리

      
단계함수하는 일
①re, collections.Counter글자로 언어 나누기, 세기
②~⑥transformers(AutoTokenizer, AutoModel), torch다국어 임베딩

      
word_kind, embed, found, mix, found_subset은 이 파일 안에서 정의한 함수예요.
