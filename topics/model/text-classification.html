문장 분류: 고정한 벡터, 미세조정, 라벨이 적을 때

모델 > 순서와 언어 모델

💡 한 문장으로

문장을 미리 학습된 모델(e5)로 벡터로 바꾸면, 그 위에 단순한 분류기만 얹어도 처음 보는 말투까지 잘 나눠요. 모델까지 고치는 미세조정은 데이터가 적으면 외우기 쉬워서, 고칠 범위를 골라야 해요. 라벨이 적으면 벡터와 라벨 없는 문장을 최대한 활용해요.

🤔 왜 필요할까?

서비스에 문의가 하루 수백 건 들어온다고 해 봐요. 버그는 개발팀, 기능 요청은 기획팀, 질문은 고객 지원팀이 봐야 해요. 사람이 하나씩 읽고 나누기에는 많아서, 글을 읽고 종류를 붙이는 모델을 만들어요. 이런 일을 문장 분류라고 해요. 스팸 거르기, 감정 분석, 의도 파악이 모두 같은 틀이에요.

이 쪽의 예제는 가상의 문의 780개예요. 종류는 셋이고, 같은 기능 이름이 세 종류에 모두 나와요.

네 가지 방법으로 같은 데이터를 풀어 봤어요.

🗺️ 통째로 한 번

데이터 → 단어 세기 기준선 → e5로 문장 벡터 → 고정한 벡터 위에 분류기 → e5까지 미세조정 → 틀린 것 살피기 → 라벨이 적을 때 → 라벨 없는 문장 쓰기. 상자를 누르면 그 단계로 가요.

왜 문장 틀이 겹치지 않게 나누나? 같은 말투가 train과 test에 다 있으면, 모델이 말투를 외워도 점수가 높게 나와요. 실제로 쓸 때는 처음 보는 사람의 처음 보는 말투가 들어와요. 그래서 test에는 train에 없던 문장 틀만 넣었어요.

코드의 ② 부분

② 기준선: 단어를 세는 모델

문장마다 단어가 몇 번, 얼마나 드물게 나왔는지 세고(TF-IDF), 종류마다 단어가 나올 확률로 판단해요(Naive Bayes).

왜 기준선부터? 무거운 모델이 얼마나 나은지 알려면 비교할 바닥이 있어야 해요. 단어 세기는 빠르고 단순해서 첫 비교 대상으로 좋아요.

TF-IDF는 "이 문장에 자주 나오고(TF) 다른 문장에는 드문(IDF) 단어"에 큰 점수를 주는 방법이에요. Naive Bayes는 "버그 문의에는 '오류'가 자주 나온다"처럼 종류마다 단어의 출현 정도를 배운 뒤, 새 문장의 단어들로 어느 종류일 확률이 높은지 계산해요. 단어끼리 서로 상관없다고 가정해서(naive) 계산이 아주 빨라요.

코드뜻

analyzer="word"띄어쓰기 단어 단위로 세기
{w for t in ... for w in t.split()}train에 나온 단어 집합

코드의 ③ 부분

③ e5로 문장 벡터 만들기 (특성 추출)

미리 학습된 e5에 문장을 넣고, 토큰 벡터들을 평균 내 문장 하나의 벡터로 만들어요. e5는 고치지 않아요.

Transformer 구조에서 본 것처럼, e5는 토큰마다 문맥이 섞인 384칸 벡터를 내요. 이걸 평균 내면(평균 풀링) 문장 하나의 벡터가 돼요. 채운 자리(padding)는 평균에서 빼요. 첫 토큰의 벡터 하나만 쓰는 방법도 있는데, e5는 평균으로 쓰도록 학습됐어요.

왜 미리 학습된 모델을 쓰나? e5는 수많은 글로 "뜻이 비슷한 문장은 가까운 벡터"가 되도록 학습돼 있어요. 우리 데이터 190개로는 배울 수 없는 언어 지식이에요. 이걸 빌려 쓰는 게 전이학습이에요(전이학습은 그림으로 같은 일을 해요). 여기서는 e5를 고정하고 벡터만 뽑아 쓰는 특성 추출 방식이에요.

코드 읽기

코드뜻
tok(["query: " + t ...], padding=True, return_tensors="pt")e5는 문장 앞에 query: 를 붙여 쓰도록 학습됐어요
mean_pool(hidden, mask)채운 자리를 빼고 토큰 벡터 평균
torch.no_grad()기울기를 계산하지 않아요. 고치지 않으니까요
F.normalize(..., dim=-1)벡터 길이를 1로

코드의 ⑤ 부분

⑤ 미세조정: 모델 안의 가중치까지 고치기

e5 위에 분류 층을 붙이고, 정답으로 손실을 계산해 e5의 층까지 함께 고쳐요. 12층 전부를 고칠 때와 위쪽 4층만 고칠 때를 비교해요.

미세조정(fine-tuning)은 미리 학습된 모델을 출발점으로, 우리 과제의 정답으로 조금 더 학습시키는 거예요. 특성 추출은 e5를 그대로 두지만, 미세조정은 e5의 가중치도 이 과제에 맞게 바뀌어요. 데이터가 넉넉하면 보통 미세조정이 더 좋아요.

왜 층 수를 고르나? 고치는 가중치가 많을수록 우리 데이터에 더 맞출 수 있지만, 데이터가 적으면 그만큼 외우기도 쉬워요. 아래쪽 층은 단어 조각, 문법 같은 일반적인 지식을, 위쪽 층은 과제에 가까운 정보를 담는다고 알려져 있어서, 데이터가 적을 때는 위쪽만 고치는 방법을 자주 써요. 새로 붙인 분류 층은 무작위에서 시작하니 학습률을 더 크게(head_lr) 줘요.

clf.body.requires_grad_(False)몸통 전체를 고정 (Embedding 표 포함)
clf.body.encoder.layer[12 - train_layers:]위에서부터 train_layers개 층
torch.optim.AdamW([{...}, {...}])몸통과 분류 층에 다른 학습률. AdamW는 가중치 감쇠를 따로 처리하는 Adam

F.cross_entropy(logits, Y[idx])세 종류의 점수와 정답으로 손실

코드의 ⑦ 부분

⑦ 라벨이 적을 때

종류마다 라벨을 n개만 남기고 세 방법을 비교해요. 라벨이 하나도 없을 때는 종류마다 설명문 한 줄로 답해요.

왜? 실제로는 라벨을 다는 게 가장 비싸요. 사람이 하나씩 읽어야 하니까요. 그래서 "라벨이 몇 개면 쓸 만한가", "라벨 없이 시작할 수는 없나"를 먼저 따져 봐요.

가장 비슷한 문장 따라가기는 라벨이 있는 문장들의 벡터를 찾아보기 표로 두고, 새 문장과 가장 가까운 문장의 라벨을 그대로 쓰는 방법이에요(KNN, k=1). 문장이 수백만 개면 FAISS 같은 벡터 검색 라이브러리로 찾아요(Embedding과 벡터 검색). 설명문으로 답하기는 라벨 대신 종류의 뜻을 한 줄로 써서 벡터로 만들고, 그 벡터와 가장 가까운 종류로 답해요. e5의 검색 학습 방식에 맞춰 문의는 query:, 설명문은 passage:를 붙였어요.

코드의 ⑧ 부분

⑧ 라벨 없는 문장 쓰기: 스스로 라벨 붙여 다시 배우기

라벨 몇 개로 배운 모델이 라벨 없는 문장에 가짜 라벨을 붙이고, 확신이 높은 것만 더해 다시 배워요. 무작위 뽑기 5번으로 비교해요.

라벨 없는 문장은 거의 공짜로 모여요. 이걸 쓰는 가장 단순한 방법이 자기 학습(self-training)이에요. 선생 모델이 붙인 가짜 라벨(pseudo-label) 중 확신이 높은 것만 골라 학생 모델이 배워요. 이걸 몇 번 되풀이하기도 하고, 확신 대신 "여러 번 물었을 때 답이 얼마나 일정한가"로 고르기도 해요(UST).

🛠️ 실제로 할 때

      
상황어떻게
데이터가 많고 GPU가 있다전체 미세조정이 보통 가장 좋아요. 학습률은 2e-5~5e-5, epoch은 2~4번이 흔한 출발점이에요. valid 점수를 보며 멈추고, 가장 좋던 때의 가중치를 저장해요(save_pretrained).
데이터가 적다먼저 ④처럼 고정한 벡터 + 단순한 분류기로 기준을 잡고, 미세조정은 위쪽 몇 층만 고쳐 봐요(⑤). 점수는 반드시 처음 보는 데이터로 확인해요.
종류가 불균형하다정확도 대신 macro F1, 종류별 recall을 봐요. 적은 종류에 무게를 주거나(class_weight) 적은 종류의 데이터를 더 모아요.
라벨이 거의 없다설명문과의 유사도(⑦)나, LLM에게 종류 설명과 예시 몇 개를 프롬프트로 주고 바로 분류시키는 방법(퓨샷)으로 시작해요. 그 결과를 사람이 고쳐 라벨로 모으면 빨라요.
라벨 없는 글이 많다그 글로 먼저 "가린 토큰 맞히기"를 더 학습해서 모델을 우리 분야 말투에 익숙하게 만든 뒤(도메인 적응) 분류를 미세조정하면 나아져요. 자기 학습(⑧)도 같이 써요.
데이터 늘리기문장을 다른 언어로 번역했다 되돌리기(back-translation), 비슷한 말로 바꾸기, 단어 일부 지우기로 라벨 있는 문장을 늘려요. 바뀐 문장도 같은 라벨이 맞는지 꼭 확인해요.
한 문장에 종류가 여럿"버그이면서 기능 요청"처럼 라벨이 여러 개일 수 있으면, 종류마다 "맞다/아니다"를 따로 맞히는 다중 라벨 분류로 바꿔요 (softmax 대신 sigmoid).
결과만 빨리 필요하다pipeline("text-classification", model=...) 한 줄로 이미 미세조정된 공개 모델을 쓸 수 있어요. 우리 종류와 같은지는 확인해야 해요.
