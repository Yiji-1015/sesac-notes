요즘 LLM의 부품: GPT-2의 블록은 어떻게 바뀌었나

모델 > 순서와 언어 모델

💡 한 문장으로

2023년 Llama 이후의 LLM도 골격은 디코더 블록을 쌓은 Transformer예요. 블록 안에서는 정규화가 RMSNorm, 작은 신경망이 SwiGLU, 위치가 RoPE, Attention이 K, V를 나눠 쓰는 GQA로 바뀌었어요. 그리고 생성할 때의 메모리와 시간을 줄이려고 KV 캐시를 다시 쓰고, 슬라이딩 윈도우와 MoE를 붙여요.

🤔 왜 필요할까?

Transformer 구조에서 GPT 같은 디코더 블록을 봤어요. 2023년 Llama 1이 공개된 뒤 가중치를 공개한 LLM이 수십 종 나왔는데, 골격은 거의 그대로예요. 디코더 블록을 쌓고, 다음 토큰을 맞히며 배워요. 바뀐 건 블록 안의 부품이에요. 바꾼 이유는 크게 셋이에요.

이유바뀐 부품
깊게 쌓아도 학습이 흔들리지 않게RMSNorm(②), Pre-norm, QK Norm
같은 계산으로 더 잘 배우게, 더 길게 쓰게SwiGLU(③), RoPE(④)
서비스할 때 메모리와 시간을 줄이게GQA(⑤), KV 캐시 재사용(⑥), 슬라이딩 윈도우(⑦), MoE(⑧)

특히 세 번째가 요즘 설계를 이끌어요. 긴 글을 여러 사람이 동시에 쓰면 모델 가중치보다 KV 캐시가 메모리를 더 차지해서, 캐시를 줄이는 방법이 모델 구조를 정해요. 흐름을 크게 나누면 이래요.

흐름시작핵심대표 모델
1. Llama 세트2023.02RMSNorm, SwiGLU, RoPE, GQA 네 가지가 기본이 됨Llama 1~3, Mistral, Cohere Command R
2. 학습 안정화 실험2024.02정규화를 늘리고(QK Norm, 블록당 여러 개), 점수 상한(softcapping)Gemma 1~4
3. 작고 효율적으로2024.04같은 부품으로 작은 모델, 긴 문맥Qwen 2~3, OLMo, Phi, SmolLM
4. 분야, 언어별2024코드, 한국어, 중국어 특화StarCoder2, InternLM, GLM-4, HyperCLOVA X SEED, ExaOne
5. MoE2023.12전문가 여럿 중 일부만 계산 (⑧)Mixtral, DeepSeek V2~V4, Qwen MoE, Solar Open
6. Transformer 너머2023.12Attention 대신 고정 크기 순환 상태 (SSM, RNN)Mamba 1, 2, RWKV v7
7. 하이브리드2024.03Attention 층과 SSM, 선형 Attention 층을 섞기Jamba, Nemotron-H, Qwen3 Next

이 쪽은 1번 흐름의 네 부품(②~⑤)과, 서비스 문제를 푸는 KV 캐시(⑥), 슬라이딩 윈도우(⑦), MoE(⑧)를 작은 모델로 직접 만들어 봐요. 모델은 받지 않고 transformers의 설정만으로 만들어서 가중치는 무작위예요. 그래서 이 쪽의 숫자는 모양, 크기, 계산 방식에 대한 것이고, 어느 모델이 더 똑똑한지는 아니에요.

🗺️ 통째로 한 번

GPT-2와 Llama를 같은 크기로 만들어 나란히 두고(①), 부품을 하나씩 바꿔 봐요(②~⑤). 그다음 생성할 때의 메모리와 시간을 다뤄요(⑥~⑧). 상자를 누르면 그 단계로 가요.

① 같은 크기의 GPT-2와 Llama

GPT2Config, LlamaConfig에 크기만 적어 모델 클래스에 넣으면, 아무것도 받지 않고 무작위 가중치 모델이 생겨요. 실제 Llama, Mistral, Mixtral도 같은 클래스에 큰 설정과 학습된 가중치를 넣은 거예요. 크기를 같게 맞추면 부품의 차이만 남아요.

코드의 ② 부분

② 정규화: LayerNorm → RMSNorm

LayerNorm은 평균을 빼고 표준편차로 나누고, RMSNorm은 평균은 두고 크기(RMS)로만 나눠요.

층을 깊이 쌓으면 벡터 크기가 층마다 커지거나 작아져서 학습이 흔들려요. 그래서 블록마다 벡터 크기를 맞춰요(Transformer 구조 ⑤의 LayerNorm).

식배우는 값
LayerNorm(x − 평균) ÷ √(분산 + ε) × γ + βγ, β (칸마다)
RMSNormx ÷ √(평균(x²) + ε) × γγ (칸마다)

RMSNorm은 평균을 구하고 빼는 계산과 β를 없앴어요. 계산이 가벼운데 성능은 거의 같아서 Llama 1 이후 기본이 됐어요.

어디에 두나: 원조 Transformer와 BERT, e5는 블록 출력 쪽에서 정규화해요(post-norm, norm(x + layer(x))). GPT-2와 Llama는 입력 쪽에 둬요(pre-norm, x + layer(norm(x))). 잔차 길이 정규화를 거치지 않아서, 깊게 쌓아도 학습이 안정적이에요. 아주 깊은 MoE 모델에서는 post-norm 계열을 다시 섞기도 해요.

QK Norm: Attention 점수를 내기 전에 Query와 Key에도 RMSNorm을 걸어요. 점수가 너무 커져서 softmax가 한 토큰에 쏠리는 걸 막아요. 2024~25년 새 모델(Qwen 3, OLMo 2, Gemma 3)에 빠르게 퍼졌어요.

코드뜻

block.ln_1(x)GPT-2 블록의 Attention 앞 LayerNorm

코드의 ③ 부분

③ 작은 신경망: GELU → SwiGLU

한 갈래가 다른 갈래의 '문'이 되는 작은 신경망이에요. 행렬이 셋이라 안쪽을 좁혀 크기를 맞춰요.

블록마다 Attention 뒤에 토큰마다 따로 계산하는 작은 신경망이 있어요. GPT-2는 down(GELU(up(x)))예요. SwiGLU는 갈래를 둘로 나눠, 한 갈래(gate)를 SiLU에 넣은 값을 다른 갈래(up)에 칸마다 곱해요.

down(SiLU(gate(x)) × up(x)), SiLU(z) = z × sigmoid(z)

gate 갈래가 칸마다 "얼마나 통과시킬지"를 입력에 따라 정하는 셈이에요. 같은 가중치 수로 더 빨리, 더 잘 배운다는 결과가 많아서 2023년 이후 표준이 됐어요. 최근에는 값이 폭주하지 않게 범위를 자르는(clamp) 변형도 써요.

코드 읽기

코드뜻
mlp.gate_proj, mlp.up_proj, mlp.down_projSwiGLU의 행렬 셋
F.silu(z)z × sigmoid(z)

이 단계까지 실행하면

코드의 ④ 부분

④ 위치: 위치 표 → RoPE

자리마다 배운 벡터를 더하는 대신, Query와 Key를 자리만큼 돌려요. 그러면 점수가 두 토큰의 거리에만 달려요.

GPT-2는 자리마다 배운 벡터(위치 표의 한 줄)를 토큰 벡터에 더해요(Transformer 구조 ②). 표의 줄 수가 곧 넣을 수 있는 가장 긴 길이예요.

RoPE(Rotary Position Embedding)는 Query와 Key 벡터를 두 칸씩 짝지어, 짝마다 자리 × 정해진 각도만큼 돌려요. 짝마다 도는 속도가 달라서 가까운 거리와 먼 거리를 함께 구별해요. Query를 i만큼, Key를 j만큼 돌린 뒤 내적하면 두 회전이 상쇄되고 i − j만큼의 회전만 남아요. 그래서 점수가 절대 자리가 아니라 거리에 달려요.

위치를 Value가 아니라 Query와 Key에만 넣고, 한 번 돌린 Key는 뒤 토큰이 와도 그대로라 KV 캐시(⑥)와도 잘 맞아요. 일부 칸만 돌리고 나머지는 뜻을 담게 두는 Partial RoPE, 층이나 Attention 종류마다 각도를 달리 하는 변형도 있어요.

apply_rotary_pos_emb(q, k, cos, sin)Query와 Key를 돌리기 (transformers의 Llama 코드 안 함수)

코드의 ⑤ 부분

⑤ Attention: K, V head를 나눠 쓰기 (MHA → GQA → MQA)

head마다 따로 갖던 K, V를 여러 head가 같이 써요. 점수 계산 방식은 같고, 저장할 K, V가 줄어요.

다음 토큰을 하나 만들 때마다 앞 토큰 전체의 K, V가 필요해서, 생성할 때는 이걸 쌓아 둬요(KV 캐시, ⑥). 그래서 K, V의 양이 곧 메모리예요.

방식Query headK, V head예
MHA88 (head마다)GPT-2, Llama 1
GQA82 (4개 head가 하나씩 같이)Llama 2 70B, Llama 3, Mistral, 요즘 대부분
MQA81 (모두 하나)PaLM, Falcon

더 줄이는 방법도 있어요. DeepSeek V2의 MLA는 K, V를 작은 잠재 벡터로 압축해 저장했다가 쓸 때 펼쳐요. 슬라이딩 윈도우(⑦)는 오래된 토큰을 지워요.

코드의 ⑥ 부분

⑥ KV 캐시: prefill과 decode, 앞부분 다시 쓰기

입력을 한 번에 계산해 캐시를 만드는 prefill과, 캐시를 읽으며 한 토큰씩 만드는 decode로 나뉘어요. 같은 앞부분의 캐시는 다시 쓸 수 있어요.

디코더는 뒤를 못 보니까(Transformer 구조 ⑦), 앞 토큰의 K, V는 뒤에 무엇이 붙어도 변하지 않아요. 그래서 한 번 계산한 K, V를 쌓아 두면, 다음 토큰은 새 토큰 하나만 계산하면 돼요. 생성은 두 단계로 나뉘어요.

단계하는 일시간을 정하는 것사용자가 느끼는 것
prefill입력 전체를 한꺼번에 계산해 캐시 만들기계산량첫 토큰까지 걸리는 시간 (TTFT)
decode캐시를 읽으며 한 토큰씩 만들기메모리 읽기 (가중치와 캐시)토큰이 나오는 속도

서빙 엔진이 하는 일: vLLM 같은 서빙 엔진은 캐시를 고정 크기 블록(예: 16토큰, 128토큰)으로 나눠 메모리에 흩어 담아요(PagedAttention). 블록 내용의 해시로 같은 앞부분을 찾아, 다른 요청이 계산한 캐시를 그대로 다시 써요(prefix caching). 시스템 Prompt, 긴 문서, 여러 턴 대화처럼 앞부분이 되풀이될수록 첫 토큰까지 시간이 크게 줄어요.

캐시를 밖으로 옮기기(offloading): GPU 메모리가 모자라면 캐시를 CPU 메모리, 디스크, 네트워크 저장소로 옮겨 뒀다가 필요할 때 가져와요. 다시 계산하는 것보다 읽어 오는 게 빠를 때만 이득이라, 짧은 Prompt는 그냥 다시 계산하는 게 나아요. 사용자가 많고 같은 앞부분을 많이 공유할수록 효과가 커요.

코드뜻

model(next_ids, past_key_values=cache, use_cache=True)decode: 캐시 뒤에 이어서 계산 (캐시에 새 토큰이 붙어요)
cache.crop(-1)캐시 끝에서 1토큰 지우기

코드의 ⑦ 부분

⑦ 슬라이딩 윈도우: 앞의 W개만 보기

전체 Attention은 점수 계산이 길이의 제곱으로, KV 캐시가 길이에 비례해서 늘어요. 슬라이딩 윈도우는 토큰마다 바로 앞 W개만 보게 해서 둘 다 W에 묶어요(Mistral 7B가 퍼뜨렸어요).

코드의 ⑧ 부분

⑧ MoE: 전문가 8개 중 2개만

작은 신경망을 여러 벌(전문가) 두고, 토큰마다 라우터가 고른 몇 개만 계산해요. 가중치는 많아도 토큰 하나의 계산은 작아요.

모델을 키우면 더 잘하지만 토큰마다 계산도 커져요. MoE(Mixture of Experts)는 블록의 작은 신경망(③의 SwiGLU)을 전문가 N벌로 늘리고, 작은 Linear 하나(라우터)가 토큰마다 전문가 점수를 매겨 상위 k개만 계산해서 가중 합해요. Mixtral은 8벌 중 2개예요.

요즘은 모든 토큰이 늘 거치는 공유 전문가를 하나 두고 나머지를 잘게 많이 나누기도 해요(Qwen MoE, DeepSeek, Solar Open). 라우터 점수도 softmax 대신 전문가마다 따로 매기는 sigmoid로 바뀌는 추세예요. 학습이 까다로운 대신, 전체 크기에 비해 계산이 작아서 큰 모델일수록 MoE가 많아요.

새 모델의 설정 읽기config.json에서 num_key_value_heads(GQA), sliding_window, num_local_experts와 num_experts_per_tok(MoE), rope_scaling(긴 문맥), tie_word_embeddings를 보면 이 쪽의 부품 중 무엇을 썼는지 알 수 있어요.
서빙 메모리 어림하기KV 캐시 = 2 × 층 수 × K, V head 수 × head 크기 × 토큰 수 × 바이트(16비트면 2)예요. 여기에 동시 요청 수를 곱하고 가중치 크기를 더해요(⑤).
첫 토큰이 느리다prefill이 길어서예요. 공통 앞부분을 앞에 모아 prefix caching이 걸리게 하고, 필요 없는 문맥을 줄여요(⑥).
토큰이 천천히 나온다decode는 메모리 읽기가 병목이라, 가중치를 작게(양자화, 모델 가볍게), KV 캐시를 작게(GQA, MLA), 여러 요청을 묶어 한 번에 읽어요.
더 빨리 생성하기 (추측 디코딩)작은 모델(drafter)이 토큰 여러 개를 먼저 제안하고, 큰 모델이 한 번의 계산으로 검사해 맞는 데까지 받아들여요. 틀리면 큰 모델의 답을 쓰니 결과는 그대로예요. 모델 안에 여러 토큰을 미리 맞히는 머리(MTP)를 같이 학습해 두기도 해요.
Attention 없는 모델Mamba, RWKV는 Attention 대신 고정 크기의 순환 상태로 문맥을 요약해서, 길이가 늘어도 메모리가 일정해요. 대신 앞의 내용을 정확히 꺼내는 데 약해서, Attention 층과 섞은 하이브리드(Jamba, Nemotron-H, Qwen3 Next)가 늘고 있어요.
