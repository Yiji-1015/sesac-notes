💡 한 문장으로

지난 기록에서 규칙을 배워 숫자를 맞히면 회귀, 종류를 맞히면 분류예요. 모델보다 먼저 기준선, 지표, 나누기를 정해야 점수가 의미를 가져요.

🤔 왜 필요할까?

"이 요청은 실패할까?", "처리에 얼마나 걸릴까?"처럼, 지난 기록으로 앞으로를 맞히고 싶을 때가 있어요. 사람이 규칙을 일일이 정하는 대신 기록에서 규칙을 배우게 하는 게 머신러닝이에요. 표(행과 열) 데이터에서는 보통 두 가지를 해요.

종류맞히는 것예
회귀숫자처리 시간 1,520 ms
분류정해진 종류 중 하나실패 / 성공

예제는 업무 요청 100건이에요.

모델을 만들기 전에 꼭 정해야 할 게 있어요. 무엇과 비교해서 잘했다고 할지(기준선), 무엇으로 잴지(지표), 어떤 데이터로 잴지(나누기)예요. 이게 없으면 "정확도 70%"가 좋은 건지 나쁜 건지 알 수 없어요.

🗺️ 통째로 한 번

나누고, 기준선을 정하고, 전처리를 묶고, 회귀와 분류를 해 보고, 같은 조건으로 비교해요. 상자를 누르면 그 단계로 가요.

requests_model.py 하나가 이 쪽(①~⑦)에서 시작해 2쪽(⑧~⑫), 3쪽(⑬~⑰)까지 자라요.

🔎 한 단계씩: 설명과 코드를 나란히

코드의 ① 부분

① 데이터 읽고 나누기

요청을 받을 때 아는 네 열만 입력으로 고르고, 행을 train, valid, test로 나눠요.

train으로 배우고, valid로 모델을 고르고, test는 마지막에 딱 한 번 성적을 매기는 데 써요. 같은 데이터로 배우고 채점하면, 답을 외운 모델도 100점이 나와요.

코드 읽기

코드뜻
pd.read_csv(...).set_index("request_id")표를 읽고, 요청 번호를 행 이름으로
manifest[manifest["split"] == name]이 쪽에 들어갈 행 번호만
raw.loc[ids]그 번호의 행만 꺼내기

코드의 ③ 부분

③ 전처리를 Pipeline으로 묶기

빈 칸 채우기, 크기 맞추기, 글자를 숫자로 바꾸기를 모델과 한 덩어리로 묶어요.

전처리를 따로 하면 실수로 valid나 test까지 보고 기준(중앙값, 평균)을 정하기 쉬워요. 그러면 채점할 데이터를 미리 엿본 셈이에요. Pipeline으로 묶으면 fit할 때 train만 보고 기준을 정해요.

코드 읽기

코드뜻
SimpleImputer(strategy="median")빈 칸을 중앙값으로
StandardScaler()평균 0, 표준편차 1로
OneHotEncoder(handle_unknown="ignore")글자 값마다 0/1 열. 처음 보는 값은 모두 0
ColumnTransformer([...])열마다 다른 전처리
Pipeline([("pre", ...), ("model", ...)])전처리와 모델을 한 덩어리로
clone(model)설정만 같은 새 모델. 같은 모델 객체를 여러 번 쓰지 않으려고

🛠️ 실제로 할 때

      
상황어떻게
데이터가 적다valid 20건이면 한두 건만 바뀌어도 점수가 크게 흔들려요. 한 번의 점수로 고르지 말고 교차검증을 써요 (2쪽).
R²가 음수모델보다 입력부터 의심해요. 처리 시간을 정말 설명할 값(서버 상태, 요청 내용 등)이 입력에 있나요?
실패가 드물다정확도 대신 recall, F1을 보고, 필요하면 확률 기준(0.5)을 바꿔요 (3쪽).
처리 후에 생기는 열status처럼 결과가 이미 담긴 열을 입력에 넣으면 점수가 비현실적으로 높게 나와요. 실제로 쓸 때는 그 값이 없어서 무너져요.
