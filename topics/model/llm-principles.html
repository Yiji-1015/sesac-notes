LLM 원리: Token, Embedding, Attention, 다음 토큰

모델 > 순서와 언어 모델

💡 한 문장으로

LLM은 글을 토큰으로 나누고, 벡터로 바꾸고, Attention으로 다른 토큰을 참고해 문맥을 섞은 뒤, 다음 토큰의 확률을 계산해 하나씩 이어 붙여요.

🤔 왜 필요할까?

LLM(대규모 언어 모델)은 지금까지의 글을 보고 다음 토큰을 맞히는 모델이에요. 그걸 수없이 반복해서 문장을 만들어요. 똑똑해 보이는 답도 결국 "다음에 올 조각의 확률"을 고른 결과예요. 그래서 그럴듯하지만 틀린 답(환각)도 나와요.

이 쪽에서는 이 길을 한 단계씩, 이 PC에 있는 실제 Transformer 모델(multilingual-e5-small, 12층)로 따라가요. 다만 이 모델은 문장을 벡터로 바꾸는 인코더라 다음 토큰을 만들지는 않아요. ⑥은 원리만 예시 점수로 계산해요.

🗺️ 통째로 한 번

글 → 토큰 → 벡터 → Attention으로 문맥 섞기 → (미래 가리기) → 다음 토큰 확률. 상자를 누르면 그 단계로 가요.

코드의 ③ 부분

③ Attention을 손으로 계산하기

토큰마다 Query, Key, Value를 만들고, Query와 Key가 잘 맞을수록 그 토큰의 Value를 많이 섞어요.

도서관에 빗대면, Query는 "내가 찾는 것", Key는 "책 등의 제목", Value는 "책 내용"이에요. 찾는 것과 제목이 잘 맞는 책의 내용을 많이 가져와요.

"잘 맞음"은 Query와 Key의 내적(칸마다 곱해 더한 값)으로 재요. 같은 방향일수록 커요. 그런데 벡터 칸 수 d가 크면 내적도 커져서(칸마다 곱한 값을 d개 더하니까), softmax가 1등 하나에 거의 다 몰려 버리고 기울기가 사라져요. 그래서 √d로 나눠 크기를 맞춰요.

여러 head: 한 번의 Attention은 한 가지 관계만 잘 잡아요. 그래서 Q, K, V 행렬을 여러 벌 두고(head) 따로 계산한 뒤 결과를 이어 붙여요. 어떤 head는 바로 앞 토큰을, 어떤 head는 주어를, 어떤 head는 따옴표 짝을 보는 식으로 나뉘어요. ⑤에서는 실제 모델의 head 12개를 평균 내서 봐요.

순서는 어디에? 이 계산에는 "몇 번째 토큰인가"가 전혀 없어요. 아래 🔁처럼 순서를 섞어도 결과가 똑같이 섞일 뿐이에요. 그래서 Transformer는 처음에 자리마다 다른 위치 벡터를 토큰 벡터에 더해요. 처음 Transformer는 사인, 코사인으로 만든 고정 벡터를 썼고, 요즘은 학습하는 위치 벡터나, Query와 Key를 자리에 따라 돌려서 "얼마나 떨어졌나"를 넣는 RoPE를 많이 써요.

코드 읽기

코드뜻
Q, K, V = x @ Wq, x @ Wk, x @ Wv같은 벡터를 세 행렬로 바꿔 세 역할로
Q @ K.T / d ** 0.5모든 토큰 쌍의 맞음 점수. √d로 나눠 너무 커지지 않게
torch.softmax(scores, dim=-1)줄마다 합이 1인 가중치
weights @ V가중치만큼 내용을 섞은 새 표현

코드의 ④ 부분

④ 뒤를 못 보게 막기 (Mask)

자기보다 뒤의 토큰 점수를 −∞로 바꿔, softmax 뒤 가중치가 0이 되게 해요.

같은 Attention에 가리는 모양만 바꾸면 Transformer의 세 갈래가 나와요. 무엇을 맞히며 미리 배우는지(사전학습 목표)도 같이 달라요.

코드의 ⑤ 부분

⑤ 실제 모델의 Attention 보기

e5 모델에 문장을 넣고, 12개 층의 Attention 가중치를 꺼내 봐요.

Transformer는 ③의 Attention(과 작은 신경망)을 한 층으로 해서 여러 층 쌓은 모델이에요. 층마다 head 여러 개가 서로 다른 관계를 봐요.

층 하나는 이렇게 생겼어요. ① 여러 head의 Attention으로 다른 토큰의 정보를 섞고, ② 입력을 그대로 더한 뒤(잔차 연결) LayerNorm(토큰 하나의 벡터 안에서 값들을 평균 0, 표준편차 1로 맞추기)으로 크기를 맞추고, ③ 토큰마다 따로 2층짜리 작은 신경망(보통 칸 수를 4배로 넓혔다가 줄여요)을 통과시키고, ④ 다시 잔차 연결과 LayerNorm을 해요. Attention은 "토큰끼리 정보 나누기", 작은 신경망은 "토큰마다 생각하기"를 맡아요. 잔차 연결과 정규화는 CNN ⑦의 ResNet과 같은 이유로 넣어요. 그래야 수십 층을 쌓아도 학습돼요.

그림도 같은 방식으로 다룰 수 있어요. 그림을 16×16 조각으로 잘라 조각 하나를 토큰처럼 쓰면 Vision Transformer(ViT)예요. CNN의 "가까운 픽셀끼리" 가정이 없어서 데이터가 아주 많을 때 강해요.

model(**enc, output_attentions=True)층마다 Attention 가중치도 돌려줘요.
torch.stack(out.attentions)(층, 배치, head, 토큰, 토큰)
a.argmax(-1)줄마다 가장 큰 가중치의 위치

🛠️ 실제로 할 때

      
상황어떻게
Context Window모델이 한 번에 볼 수 있는 토큰 수의 한도예요. 대화가 길어지면 앞부분이 잘려서 "잊어버린" 것처럼 보여요. 그래서 필요한 자료만 골라 넣어요 (Prompt와 출력 계약).
한국어는 토큰이 많다같은 뜻이라도 영어보다 토큰이 많이 나오는 편이라 비용과 한도에 영향을 줘요. 실제 토큰 수는 그 모델의 Tokenizer로 세요.
환각모델은 "사실인가"가 아니라 "그럴듯한가"로 다음 토큰을 골라요. 근거 자료를 주고(RAG), 답을 검사하는 이유예요.
학습과 추론학습은 엄청난 글로 가중치를 정하는 일이고, 우리가 API로 쓰는 건 정해진 가중치로 다음 토큰을 계산하는 추론이에요.
긴 문맥이 느리고 비싸다Attention이 토큰 수의 제곱으로 늘어서예요(⑤의 🔁). 필요한 부분만 넣고(RAG), 같은 앞부분을 반복해서 보낼 때는 캐시를 쓰는 API 기능을 활용해요.
글 만들기와 검색, 어떤 모델?글을 만들려면 디코더(GPT식 LLM), 문장을 벡터로 바꿔 비슷한 걸 찾으려면 인코더(e5 같은 Embedding 모델)를 써요. 갈래가 달라서 서로 대신 쓰기 어려워요 (④의 표).
큰 모델의 점수는 어디서 왔나사전학습은 다음 토큰(또는 가린 토큰) 맞히기 하나로 엄청난 글을 배우는 거예요. 지시를 따르는 대화형 LLM은 그 뒤에 질문과 좋은 답 쌍으로 더 배우고(미세조정), 사람의 선호로 다듬어요.
